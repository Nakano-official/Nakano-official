### [takeover](https://github.com/Nakano-official/takeover) — 大学の障がい学生支援室の業務システム

シフトに欠員が出たら候補者を自動抽出し、Google Chat で代行を依頼、
最初に承諾した人へ先着で確定するところまでを自動化しました。
要件ヒアリングから設計・実装まで担当。個人情報は学内 Google Workspace 内で完結させています。

Google Apps Script / 約7,100行

### HATOBA — フロントエンド担当

賞味期限間近の食材を使って、スーパーのイートインを大学生向けの「夕食食堂」に変える提案です。
店員が値引き商品を撮影すると AI がメニューを提案し、材料費・人件費・販売価格はコード側で計算。
学生はアプリで当日のメニューを見て、席のバーコードから注文する——という流れで、
**スーパーの若年層の取り込み・学生の食費・フードロスを同時に解く**ことを狙いました。

龍谷大学スマートライフハッカソン（平和堂 × ソフトバンク・2026年6〜7月）で **2位**。
6人チームでの開発で、フロントエンドを担当しました。

Next.js / TypeScript / Gemini API ・ [リポジトリ](https://github.com/shimizu-kiichi/HATOBA)

### [Loop-Engine](https://github.com/Nakano-official/Loop-Engine) — AI に実装を任せるループの実行基盤

仕様と受け入れ条件を作る側、関門を機械的に適用する側、隔離環境で実装する側を分離し、
「テストが通りました」という AI の自己申告に頼らずに開発ループを回すための基盤です。
実装前にテストが落ちること（Red）を確認し、実装中はテストを凍結して書き換えを封じ、
権限は信頼ではなく OS のユーザー分離で担保しています。

**要件6行から11ステップを人間の介在ゼロで通し切った実行**があります（全ステップ1回の試行で緑・48件パス）。
検証手段が Python + pytest に結合しているため、他言語への一般化はこれからです。

Python / WSL2 ・ ランナー本体は標準ライブラリのみ約2,300行
